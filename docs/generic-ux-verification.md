# 범용 앱 브랜딩 및 상세 튜토리얼 UX 개선

## 변경 범위와 데이터 보존

- 로그인과 PC·모바일 공통 헤더/사이드바는 `APP_BRAND`의 현장관리를 사용합니다. 회사명은 업무 데이터와 문서 프로필로 유지합니다. 내부 패키지명·회사 ID·기존 계정·샘플 현장명은 호환성을 위해 바꾸지 않습니다.
- `DEFAULT_COMPANY`, 견적서 기본 회사정보, XLSX 원본, 로고/직인 추출 및 배경제거 경로는 보존합니다. 견적별 회사정보는 기존 스냅샷 계약을 그대로 사용합니다.
- 견적 작성 하단 고정 액션은 회사정보 / 프로필 변경·거래처·미리보기·저장을 제공합니다. 모바일에서는 하단 내비게이션과 안전영역 위에 표시합니다.
- 회사 프로필 창은 닫기/취소 시 견적을 바꾸지 않습니다. **이번 견적에만 적용**은 작성 중인 견적만 수정하며 견적 저장이 필요합니다. **회사 기본정보 저장**은 관리자에게만 제공하며, 최신 회사 설정을 읽어 다른 설정을 보존합니다. 과거 견적 스냅샷을 동결한 뒤 새 기본값을 저장합니다. 이 버튼만 눌러서는 현재 견적 초안의 회사정보를 교체하지 않습니다.
- 품목 한 건씩 추가·연속 입력 흐름과 숫자 빈 입력을 유지합니다. 미확정 수량/단가의 고객 출력 셀은 비우고, 명시적으로 입력한 무료 단가 0은 유지합니다. 고객 DTO에 원가·마진을 추가하지 않습니다. 빈 회사·거래처 정보 및 빈 품목은 고객 출력에서 제외하며 기존 양식의 배치와 합계는 유지합니다.

## 실습과 초기설정

튜토리얼 버전은 2입니다. 관리자 13단계, 직원 13단계, 작업진행자 11단계를 제공합니다. 견적 권한이 없는 직원에게는 견적 실습 2단계를 표시하지 않습니다. 회사/사용자/역할/버전별 별도 저장소를 사용하며, 예시 ID는 `tutorial:` 접두사와 소유 정보를 갖습니다.

전체 앱 소개, 홈, 견적, 현장, 일정, 작업진행자, 일일작업, 사진, 자재, 정산(작업진행자는 본인 정산), 완료보고서, A/S, 작업지시를 해당 역할에 맞게 안내합니다. 각 단계는 지정된 예시 필드를 수정하고 서버에 **예시에만 저장**한 결과를 확인해야 다음 단계로 진행할 수 있습니다. 건너뛰기는 가능합니다. 일정에는 관리자 전체 일정·직원의 허용 현장·작업진행자의 본인 배정과 작업지시 연결을 설명하며, 현장에는 견적부터 사진·자재·정산·완료보고서·A/S까지의 연결을 안내합니다.

실습은 별도 저장소의 예시를 실제로 편집하는 방식입니다. 실제 업무 저장소에 연습용 일정·사진·수금 원장을 만들지 않습니다. 사진 선택은 로컬 미리보기이며 다른 계정에 실습 알림을 보내지 않습니다. 기존 공용 체험 샘플과 별도의 개인 실습 예시를 구분해서 표시합니다. 종료 시 개인 예시만 삭제하며, 도움말에서 재생성·개별 되돌리기·튜토리얼 다시보기가 가능합니다.

초기설정은 9단계입니다. 첫 일정 완료 여부는 실제 현장에 연결된 대표 작업진행자/날짜가 있는 일일작업 기록으로 판단합니다. 튜토리얼 저장소를 진행률 근거로 사용하지 않습니다. 신규 가입 양식은 실제 입력값 없이 빈 상태로 시작하고 예시는 placeholder에만 표시합니다. 가입 승인·계정 생성·권한 부여 방식은 기존 흐름을 유지합니다.

## 검증 방법

필수 회귀 검증:

```sh
npm run build
npm test
npm run typecheck
```

브라우저 검증은 빌드 후 **폐기 가능한 로컬 sample 인스턴스**에서 실행합니다. Chromium, Playwright, `pdftotext`가 필요합니다. 운영 URL을 지정하면 스크립트가 거부합니다. 의존성 선언과 lockfile은 바꾸지 않았습니다.

```sh
npm run start:preview
# 다른 터미널: Playwright를 사용할 수 있는 환경에서
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/verify-generic-ux.cjs
```

검증 항목:

- PC 1440×1000, iPhone 크기 390×844, Android 크기 412×915
- 역할별 전체 실습의 편집/저장/완료, 삭제/재생성 및 실제 현장 자료 불변
- 가입 회사명 빈 값, 체험 안내 팝업, 초기설정 9단계 진행률
- 위·아래 스크롤 위치에서 고정 액션의 화면 내 배치와 다른 요소에 가려지지 않는지 확인
- 회사 프로필의 이번 견적 적용과 회사 기본값 저장 구분, 과거 스냅샷 불변
- 품목 한 건 추가 후 입력칸 초기화, 실제 UI 견적 저장, PDF 텍스트와 XLSX 품목/담당자 내용
- 모바일 월간 캘린더, 뒤로가기와 왼쪽→오른쪽 스와이프의 미저장 확인
- PWA standalone 환경 모사, manifest, 서비스 워커, 오프라인 안내, API 캐시 제외

스크린샷과 내보낸 검증 문서, 결과 JSON은 기본적으로 `/tmp/generic-ux`에 생성됩니다. 로그인 세션이나 비밀정보는 결과에 기록하지 않습니다.

## 제한사항과 배포

모바일 검증은 Chromium에서 화면 크기와 터치를 모사한 결과입니다. 실제 iOS Safari/Android 기기 설치와 운영체제 고유 뒤로가기 제스처는 별도 기기 검증이 필요합니다. PWA는 서비스 워커/manifest/오프라인 동작과 standalone 모사를 확인하며 실제 홈 화면 설치를 수행하지는 않습니다.

기존 앱의 현장·견적·사용자 등 대부분의 저장소는 메모리 기반이고 자재 영구저장은 설정에 따릅니다. 체험 서비스 운영자가 보존할 실제 자료가 없음을 확인한 상태에서 재배포를 진행합니다. 이번 변경은 운영 DB 생성·마이그레이션·기존 Render 설정 변경을 포함하지 않습니다. GitHub main 반영 후 서비스의 `/api/auth/config`에 나온 `buildVersion`이 푸시한 SHA와 일치하는지와 `/api/health` 응답으로 배포를 확인합니다.
