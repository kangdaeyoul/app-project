# A/S 관리

A/S는 회사에 귀속되는 접수·처리 메타데이터이며 반드시 기존 현장에 연결됩니다. 별도의 작업/사진/지출 저장소를 만들지 않습니다. 작업기록은 기존 daily_work 및 참여자, 사진은 photo_records, 비용은 expenses, 견적은 quotes를 참조합니다.

## 처리 흐름

현장 상세의 A/S 이력 또는 독립 A/S 관리 메뉴에서 접수합니다. 예정일/시간과 작업진행자를 배정하면 기존 일일작업이 생성됩니다. 가용상태와 시간중복 경고는 기존 스케줄 서비스를 사용하며 관리자만 충돌을 확인한 뒤 강제 저장합니다. 완료정보(완료일, 처리결과, 최종 조치)를 입력한 후 관리자 결과확인과 종결을 구분합니다. 같은 위치·설비의 반복 접수 수와 이전 A/S 연결을 제공합니다.

접수/작업 전/작업 중/작업 후/시험 사진과 첨부파일은 기존 파일 저장 인터페이스를 사용합니다. 접수 사진은 아직 일일작업이 없어도 등록 가능합니다. 전후 사진만 해당 일일작업의 기존 사진 건수에 반영합니다. 결과보고서는 처리결과+전후사진, 사진대지만, 처리결과만의 실제 PDF를 지원합니다. 회사 설정명과 한글 폰트를 사용하며 고객 서명란은 없습니다.

## 금액과 보안

원공사 계약금액은 변경하지 않습니다. 유상 A/S의 승인된 신규 견적을 계약전환하면 기존 현장에 A/S 매출로 반영합니다. A/S 작업에 연결된 지출은 A/S 비용이며 기존 총 현장지출에 한 번만 포함됩니다. 현장 전체 차익 = 원공사 매출 + A/S 매출 - 전체 현장지출입니다. 삭제된 접수의 기존 매출/비용과 감사이력은 유지됩니다. 기존 견적 단가 및 사용자 수정값을 자동 갱신하지 않습니다.

관리자는 전체 관리·금액 조회·종결, 사내직원은 현장 접근범위 내 조회/입력, 작업진행자는 본인 배정 건의 작업/사진 입력만 가능합니다. API는 신뢰된 CompanyIdentityProvider의 workerId를 사용합니다. 브라우저의 회사/사용자 헤더를 신뢰하지 않습니다. 작업진행자 응답에서 매출/비용/견적 참조를 제외하고 전역 금융 API도 차단합니다. 실제 로그인은 현재 범위에 포함하지 않습니다.

## 영구저장 이전

현재 메모리 저장소이므로 API 재시작 시 접수와 파일이 초기화됩니다. PostgreSQL 이전 시 after_service_requests(company_id, site_id, previous_id, receipt/assignment/result fields), after_service_links(대상 종류/ID), after_service_attachments, 상태 설정 테이블로 분리할 수 있습니다. daily_work/photo_records/expenses는 기존 엔티티의 관계를 유지합니다. 접수 사진의 daily_work_id는 nullable로 이전하고 after_service_id 및 site_id를 유지합니다. 사진 원본을 수정하지 않으며 PDF 저장키는 회사/현장/07 A/S 하위에 배치합니다. NAS, 고객 접수, 알림, 통계 구현은 독립 어댑터로 확장할 수 있습니다.

## 검증

API 통합 테스트는 접수, 연결 검증, 배정 충돌, 작업/사용자재, 5종 사진, 무상 비용, 유상 견적 계약전환, 원계약 보존, 재발 연결, 결과확인/종결, 3종 실제 PDF, 회사 분리, 본인 접근과 금융 차단을 확인합니다.

최종 검증: 전체 API 테스트 60개 통과, 전체 빌드/타입검사 통과. PC에서 접수·사진 업로드·유상 견적 편집기 연결·달력 A/S 태그·대시보드 알림 확인. 390px 모바일에서 가로 넘침 없음과 작업진행자 본인 배정 목록/비용 비노출 확인. 브라우저 다운로드 PDF는 A4 2페이지, 한글 텍스트 추출 및 실제 이미지 2장 확인.
