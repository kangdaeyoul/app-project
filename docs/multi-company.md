# 회사 단위 확장 구조

현재 API/화면/출력 기능은 유지하며 회사 단위 분리 기반을 적용했습니다. 현재 공개 실행은 종로소방 샘플 관리자 1개이며 회원가입·로그인·요금제·결제·회사 전환 UI는 없습니다. 두 번째 회사 생성 및 전환은 서버 코드와 자동 테스트에서만 수행합니다.

## 점검 결과와 개선

기존에는 모든 저장소 인스턴스와 임시 파일을 전역으로 공유했습니다. 회사 조건 없이 조회하면 다른 회사 데이터가 섞일 수 있는 구조였습니다. 회사명은 관리자 화면, PDF 및 사진대지 기본값에 직접 들어 있었고 Excel은 종로소방 양식만 존재했습니다.

이제 `CompanyContext`에서 서버가 결정한 회사와 사용자 소속을 확인합니다. `CompanyIdentityProvider`는 향후 인증 어댑터 교체 지점이며, 현재 어댑터는 고정된 종로소방 샘플 신원만 반환합니다. 요청별 `AsyncLocalStorage` 문맥을 설정하므로 비동기 PDF 처리나 동시에 여러 회사 요청을 처리해도 회사가 바뀌지 않습니다. 회사 헤더/본문을 신원 선택에 사용하지 않으며 다른 회사 소유권을 주장하는 요청은 거부합니다.

모든 기존 저장소 인터페이스를 유지하고 DI에서 `companyRepository`로 감쌉니다. 메모리 파티션은 `{companyId, adapter}` 형태의 필수 회사 소유권을 가지며, 회사마다 독립된 어댑터와 모든 자식 컬렉션을 보유합니다. 종로소방 파티션만 기존 샘플을 초기화하고 다른 회사는 빈 상태에서 시작합니다. 조회·등록·수정·삭제·집계가 모두 현재 파티션에서 수행됩니다. 동일 ID가 다른 회사에 존재해도 서로 영향을 주지 않습니다. 기존 서비스의 거래처/현장/작업진행자 연결 검증도 현재 회사 저장소만 사용합니다.

현재 메모리 행마다 `companyId`를 중복 저장하거나 공개 DTO를 일괄 변경하지 않습니다. 메모리 어댑터 전체가 하나의 회사에 소유됩니다. PostgreSQL 저장 모델에서는 공유 계약 `CompanyOwned<T>` / `CompanyDataModel`의 **필수** `companyId`를 각 행에 적용해야 합니다. 회사 소유권을 단순 선택 필드로 두어 누락을 허용하는 방식은 사용하지 않습니다.

| 데이터 | 현재 회사 범위 |
|---|---|
| 사용자/시스템 권한 | 신원과 회사별 membership. 작업진행자의 직무·표시명과 별도 |
| 거래처/현장/견적 | 회사별 고객·현장·견적 저장소; 견적 을지/항목도 같은 어댑터 내부 컬렉션 |
| 작업진행자/휴무 | 회사별 작업진행자, 휴무 Map, 작업이력 |
| 일일작업/참여자/사용자재 | 회사별 작업/참여자/자재 카탈로그/사용내역 컬렉션 |
| 사진/파일 | 회사별 사진 메타데이터와 원본 파일 저장소 |
| 구매/경비/정산대상 | 회사별 지출/구매 수량/작업진행자 정산 항목 |
| 수금/작업진행자 지급 | 회사별 수금/지급/배분 컬렉션. 집계도 같은 회사 범위 |
| 세금계산서/증빙 | 회사별 매출/매입/작업진행자 계산서와 해당 회사 지출 참조 |
| 출력 파일/견적 양식 | 회사별 사진대지 저장소와 회사 설정의 전용 견적 양식 참조 |

## 회사 설정과 브랜드

공통 앱 브랜드 `APP_BRAND` / `APP_NAME`은 임시값 `현장관리`입니다. 회사 계정 설정은 `Company`로 분리합니다. 종로소방 기본값은 `DEFAULT_COMPANY`에 한 곳으로 모았습니다. `/api/company/current`는 현재 회사 설정, 공통 브랜드 및 현재 사용자 소속을 조회하는 읽기 API입니다.

회사명, 표시명, 로고 URL, 인장 키, 전화/팩스/이메일/주소/홈페이지/사업자정보, 견적 양식, 기본 출력 문구를 설정할 수 있는 모델입니다. 내부 `configure` 포트는 현재 회사 관리자만 같은 회사 설정을 갱신할 수 있습니다. 등록/설정 변경용 공개 API나 화면은 만들지 않았습니다. 현재 사이드바의 J 표시는 유지하고, 회사에 logoUrl이 있으면 같은 위치에 로고를 표시합니다. PDF 회사명, 사진대지 기본 회사명/제목, 새 계산서의 회사 사업자정보 기본값, Excel 회사정보는 현재 회사 설정을 사용합니다. 기존에 저장된 계산서 당사자 정보를 새 설정으로 덮어쓰지 않습니다.

종로소방 Excel 양식의 로고·인장 이미지 및 셀 서식은 해당 전용 템플릿에 그대로 보존합니다. `CompanyTemplateResolver`는 현재 회사의 등록된 템플릿만 해석합니다. 다른 회사에 템플릿이 없으면 명시적인 오류를 반환하며 종로소방 양식을 대신 쓰지 않습니다. 사용자 제공 경로를 직접 파일시스템 경로로 해석하지 않습니다. 향후 custom 양식 등록 시 회사 소유 파일 참조, 템플릿 검증과 렌더러 등록을 함께 구현해야 합니다.

## 파일 저장소

원본 파일과 생성 문서 저장소 모두 회사별 파티션으로 분리되어 같은 키라도 다른 회사에서 조회/수정할 수 없습니다. 신규 사진 키는 `companies/{companyId}/photos/{photoId}`, 생성 사진대지는 `companies/{companyId}/{siteId}/05 현장사진/사진대지/...`를 사용합니다. 기존 샘플 키는 호환성을 유지하며 종로소방 파티션에만 존재합니다. NAS 연결 시 경로는 서버 회사 문맥과 파일 메타데이터에서 생성하고, 조회는 파일을 소유한 회사 및 현장 접근 검증 후 수행해야 합니다. `CompanyFileReference`에 사진/영수증/출력/로고/인장/견적 양식 종류를 정의했습니다.

## 권한 및 PostgreSQL 이전

시스템 사용자 역할은 회사별 admin/member/viewer입니다. viewer는 회사 저장소를 읽을 수 있지만 쓰기는 거부됩니다. 기존 견적의 내부 원가/마진 조회·관리 권한은 회사 admin에게만 허용합니다. 고객용 견적 DTO/PDF는 기존 원가 제외 정책을 유지합니다. 화면의 관리자/샘플 표시와 실제 로그인 없는 운영 방식은 현재 단계에서 유지합니다.

향후 실제 인증을 적용할 때는 고정 샘플 신원 어댑터와 문맥 밖의 샘플 기본값을 제거하고, 인증 누락을 거부해야 합니다. 사용자 소속을 DB에서 검증한 뒤 서버에서 문맥을 설정하고, 백그라운드 작업도 명시적인 회사 신원으로 실행해야 합니다. 이번 변경만으로 공개 다중 회사 서비스의 인증이 완성되는 것은 아닙니다.

PostgreSQL 구현 시 아래를 저장소의 필수 계약으로 적용합니다.

- `companies` 및 `users`, `company_memberships(company_id,user_id,role)`를 두고 모든 주요 테이블과 연결 테이블에 `company_id NOT NULL` 적용.
- 현장/작업진행자/견적/사진 등 PK 또는 unique key는 `(company_id,id)`. 회사별 목록/날짜 인덱스도 company_id를 선두에 둠.
- 현장 연결은 `(company_id,site_id) REFERENCES sites(company_id,id)`. 일일작업 참여자, 자재사용, 사진, 견적 을지/항목, 지급 배분, 계산서도 **회사 ID를 포함한 복합 FK**로 연결.
- 모든 SELECT/UPDATE/DELETE에 `company_id = 서버 문맥` 조건. INSERT의 company_id는 본문 값이 아닌 서버 문맥에서 설정.
- 요청별 트랜잭션에서 회사 설정을 적용하고 PostgreSQL RLS로 이중 보호. 풀 연결에 회사 설정이 남지 않도록 `SET LOCAL` 사용.
- 현장 전환·지급 배분·일일작업 및 자식 교체는 같은 회사 트랜잭션으로 처리. 회사 식별자와 외래키를 클라이언트 입력으로 재귀 변경하지 않음.

## 검증

API 회귀 테스트에 두 회사의 모든 저장소 초기 상태, 같은 ID의 격리, 교차 회사 연결 거부, 자재/사진/경비/지급 및 파일 분리, 회사별 관리자/읽기 권한, 회사 헤더/본문 위조, 비동기 동시 문맥, 다른 회사의 종로소방 템플릿 사용 차단을 추가했습니다. 기존 기능/Excel/PDF 테스트도 함께 실행합니다.
