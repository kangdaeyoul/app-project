# 디자인 가이드 및 작업진행자 스케줄

컨셉: **현장을 아는 소방 실무자의 디지털 작업수첩**. 전문적이고 정돈된 업무 화면에 필요한 안내만 친근하게 전달합니다.

## 디자인 규칙

- 주 색상 네이비 `#243d53`, 보조 블루그레이 `#60778a`, 배경 `#f4f6f8`, 강조 오렌지 `#c76b16`.
- 그린은 완료, 앰버는 확인/충돌, 레드는 긴급/오류. 상태는 항상 텍스트와 함께 표시합니다.
- 카드 10px, 버튼 8px, 입력 7px. 모바일 입력/버튼 기본 높이 44px.
- Pretendard → Noto Sans KR → 시스템 산세리프 폰트. 금액, 현장명, 상태를 명확하게 구분합니다.
- 로고 없는 흰 안전모/남색 작업복의 벡터형 도우미를 대시보드 인사에 사용합니다. `FieldHelper`의 pose 키는 기본/인사/작업/완료/경고/사진/견적 확장을 위한 식별자이며 현재 그림은 공통입니다. 로그인 기능은 추가하지 않습니다.
- 모바일은 작업진행자별 날짜 카드가 기본이며 필터는 접어서 표시합니다. 표 보기로 전환하면 작업진행자 열을 고정하고 날짜 영역만 가로 스크롤합니다. 월간/주간 달력은 좁은 화면에서 날짜 카드로 전환합니다.

## 원본 데이터와 저장

별도의 스케줄 저장소는 없습니다. `GET /api/worker-schedule?from=YYYY-MM-DD&to=YYYY-MM-DD`가 현장 + 일일작업 + 참여 작업자를 조회 전용으로 조합합니다. 최대 63일을 조회합니다. 같은 현장/날짜에 일일작업이 있으면 현장기간으로 생성한 보조 카드는 제외합니다. 일일작업이 없으면 공사기간 기반의 시간 미정 예정 카드를 표시합니다.

`daily_work`에 예정 시작/종료(`plannedStartTime`, `plannedEndTime`), 일정종류(`scheduleKind`), 긴급(`urgent`), 확인필요(`reviewRequired`) 필드를 준비합니다. 실제 작업 시작·종료, 사진, 사용자재와 구분하여 저장하고 기존 입력 화면에서 누락해도 기존 예정정보를 보존합니다. 참여 작업자는 기존 관계 테이블 구조를 유지합니다. PostgreSQL 이전 시 기존 company_id + site_id + worker_id 관계와 날짜/시간 인덱스를 사용합니다.

`POST /api/worker-schedule/assign`은 기존 일일작업을 수정하거나 새 작업예정 기록을 등록합니다. 미배정 현장은 대표 작업진행자도 연결합니다. 시작·종료 예정시간은 필수이며 같은 날 여러 작업을 등록할 수 있습니다.

## 충돌과 권한

- 휴무, 오전불가(12:00 전), 오후불가(12:00 후)와 겹치거나 기존 일정과 시간이 겹치면 HTTP 409와 warnings를 반환합니다. 시간이 미정인 다른 배정도 확인 대상으로 표시합니다.
- 관리자가 경고를 확인하고 `force: true`를 선택하면 저장합니다. 확인 사실/경고는 일일작업 비고 및 기존 감사로그에 남습니다. 직원 범위 밖 일정과 충돌해도 현장명을 노출하지 않습니다.
- 회사 문맥은 기존 서버 신원 어댑터만 설정합니다. 클라이언트 헤더로 사용자/회사/권한을 설정하지 않습니다. 현재 로그인 없는 샘플 환경에서는 기존 샘플 관리자를 사용합니다.
- 관리자는 회사 전체 조회/수정/강제 배정/색상 변경을 할 수 있습니다. 직원은 `accessibleSiteIds` 범위 조회, 신뢰된 서버 설정 `canEditSchedule`가 허용된 경우 수정합니다. 작업진행자는 문맥의 `workerId`로 본인 일정/가용상태만 조회하고 배정/강제저장/색상변경을 할 수 없습니다.
- 각 회사 저장소에서 고유색을 자동 배정하고, 비활성화 후에도 기존 색상을 유지합니다. 관리자는 스케줄 일정표에서 색상을 수정합니다.

월간/주간은 하나의 작업 카드에 여러 작업자 태그를 표시합니다. 작업진행자별 일정표에서는 같은 원본 카드를 해당 작업자 행에 각각 투영합니다. 추가 일정은 `+N 더보기`로 조회합니다. 필터는 작업진행자/작업일자/상태/공종/현장/긴급/배정 여부를 조합합니다.

## 향후 연결

일정 배정 API와 조회 DTO를 Flutter, 드래그앤드롭, 푸시/변경알림, 외부 캘린더의 경계로 사용합니다. 실제 외부 서비스는 연결하지 않았습니다. 현재 메모리 저장은 서버 재시작 시 샘플로 초기화됩니다.

## 검증

API 회귀 테스트에 조회 원본/복수 작업/가용상태/시간중복/강제 권한/본인 조회/현장 범위/회사 격리/색상 보존/기존 사진 및 실제 작업시간 보존 검증을 추가했습니다. 브라우저 검증 결과는 `docs/verification-worker-schedule.md`를 참고하세요.
