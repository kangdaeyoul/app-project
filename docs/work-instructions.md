# 현장·A/S 작업지시와 알림센터

현재 저장소에는 독립 알림센터가 없어 이번에 공통 알림센터를 추가했습니다. 기존 대시보드 경고 카드와 A/S 기능은 유지합니다. 현장 상세 또는 A/S 상세의 작업지시 탭에서 관리자가 발송하며, 알림센터에서 작업진행자가 본인 수신 메시지를 확인합니다.

## 대상 및 읽음확인

- 개인: 현재 회사의 활성 작업진행자 1명. A/S에서는 해당 건 배정 작업진행자를 대상으로 합니다.
- 전체: 현장 대표 작업진행자 및 기존 일일작업/A/S의 참여 작업진행자. 비활성자는 새 발송 대상에서 제외하며 과거 수신 이력은 유지합니다.
- A/S 담당자: 해당 A/S의 대표 작업진행자 1명.

제목, 내용, 중요 여부, 회사/현장/A/S, 신뢰된 발신자 정보, 발송 시각을 저장합니다. 수신자는 별도 읽음 시각 및 실제 읽은 사용자 ID를 가집니다. 메시지를 열면 본인 수신 건만 읽음 처리하며 재조회해도 최초 읽음 시각이 바뀌지 않습니다. 관리자가 열어도 작업진행자의 읽음 상태를 대신 변경하지 않습니다. 중요 미확인 지시는 상단 강조 카드로 표시하고 확인 후 강조를 해제합니다. 관리자 화면의 읽음 분모는 실제 발송 수신자 수입니다.

## 중복 방지

회사 + 현장 + A/S + 정규화한 제목/내용 + 수신 작업진행자를 기준으로 이미 발송한 메시지를 검사합니다. 동일 내용의 재발송은 알림 이벤트를 만들지 않고 기존 읽음 상태를 보존합니다. 일부 수신자에게만 이미 발송했다면 나머지에게만 전달합니다. 비교 시 연속 공백을 정규화하며 기간 제한은 없습니다. 향후 반복 공지 정책이나 재발송을 추가할 때 명시적인 새 지시/버전으로 구분할 수 있습니다. 현재 메모리 어댑터는 동기 처리로 검사와 저장 사이에 비동기 경쟁이 없습니다. PostgreSQL 이전 시 수신 중복키의 unique 제약과 트랜잭션을 사용해야 합니다.

## 알림 이벤트 분리

InstructionRepository의 messages와 events는 독립 컬렉션입니다. 메시지 본문 및 수신 읽음 상태는 work_instructions/work_instruction_recipients에 해당하고, Flutter 푸시를 위한 발송 이벤트는 notification_events에 해당합니다. 이벤트에는 회사, 메시지 참조, 수신 작업진행자, 생성 시각, 이벤트 종류, 전달 대기 상태만 저장합니다. 실제 푸시/SMS는 전송하지 않습니다. 작업지시 이벤트의 읽음 여부는 메시지 수신 레코드를 조회하므로 중복 상태를 저장하지 않습니다. A/S 자체 이벤트는 메시지가 없으므로 이벤트별 읽음 시각을 독립 저장합니다. 알림센터와 배지는 15초 간격 및 읽음/발송 시 새로고침합니다.

파일 참조 배열과 첨부 여부 필드를 준비했습니다. 현재 첨부파일은 없으며 답변, 사진/파일 업로드, 관리자 확인, 완료처리는 다음 단계입니다. 메시지 본문과 전달 이력은 이후 기능에서 덮어쓰기보다 별도 관계형 엔티티로 확장합니다.

## 권한과 회사 격리

관리자만 발송/전체 읽음 조회가 가능합니다. 작업진행자는 서버가 확인한 workerId에 연결된 수신 메시지와 알림만 조회하며 타인 메시지를 읽음 처리하거나 발송할 수 없습니다. 회사는 서버 CompanyIdentityProvider로 결정됩니다. 브라우저의 회사/사용자 값은 신뢰하지 않습니다. 메시지와 이벤트 저장소는 회사별로 분리됩니다.

알림에서 현장/A/S 상세로 이동할 수 있습니다. 작업진행자 현장 상세는 본인 메시지가 있는 현장의 이름·주소·연락처·작업내용과 본인 일일작업만 제공하는 안전한 조회 경로를 사용합니다. 계약금액/회사 비용/차익이나 다른 작업진행자 지급액은 반환하지 않습니다. A/S 상세는 기존 배정 권한을 그대로 사용합니다.

현재 메모리 방식이므로 API 재시작 시 메시지·읽음·이벤트 데이터는 초기화됩니다.

검증: 전체 빌드·타입검사 및 API 테스트 61개 통과. PC 브라우저에서 현장 전체 발송·중복 차단·관리자 수신자별 읽음 시각, A/S 담당자 발송·본인 알림·상세 이동 확인. 모바일 390px에서 본인 현장 상세 및 메시지 가로 넘침 없음, 중요 메시지 읽음 후 강조 해제 확인.

A/S 확장 이벤트: 작업지시와 독립된 A/S 배정·변경·완료·재확인·종결 이벤트를 같은 알림 저장소에서 종류별로 관리합니다. A/S 이벤트는 instructionId가 빈 값이고 asId/siteId를 참조합니다. 알림센터에서 대상 A/S로 이동하거나 본인 이벤트를 읽음 처리합니다. 실제 푸시 전달 상태와 앱 내 읽음 상태는 분리됩니다. 영구저장 이전 시 종류별 참조 무결성과 회사 ID 제약을 적용합니다.
