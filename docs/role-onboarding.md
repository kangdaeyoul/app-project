# 역할별 튜토리얼과 입력 가이드

## 사용 방법

첫 로그인 시 관리자 7단계, 사내직원 6단계, 작업진행자 6단계의 짧은 가이드가 나타난다. 실제 화면으로 이동하고 등록 버튼 또는 해당 화면 제목을 강조한다. 버튼이 없는 권한/화면에서는 제목을 강조하며 사용자가 직접 선택하도록 안내한다. 자동으로 업무 등록/저장/삭제 버튼을 누르지 않는다. 이전·다음·건너뛰기를 지원한다.

각 주요 화면의 `? 도움말`에서 현재 화면 설명, 튜토리얼 다시보기, 예시 생성·삭제, 진행상태 초기화를 선택한다. 모바일 더보기에서도 도움말을 열 수 있다. 재시작 전에는 미저장 내용을 먼저 저장하도록 안내한다. 마지막에는 `예시 데이터 삭제하고 시작`, `예시 데이터 유지`, `튜토리얼 다시보기`를 선택한다.

사내직원의 견적 작성 권한이 없으면 해당 단계는 작업지시 안내로 대체한다. 작업진행자는 회사 재무 예시 대신 본인 정산 예시만 제공한다. 관리자용 기능에 대한 API 권한을 튜토리얼이 추가하지 않는다. 모바일 등록/사진/보고서 접근은 기존 현장·작업·사진·보고서 컴포넌트를 재사용한다.

## 예시 데이터는 별도 체험 영역

예시 거래처·현장·견적·작업진행자·일정·작업·사진·사용자재·정산·완료보고서를 가이드와 도움말의 **체험용 · 실제 데이터 아님** 영역에서 제공한다. 업무 목록에 예시를 끼워 넣거나 실제 업무 입력란을 예시 값으로 채우지 않는다.

- 모든 예시 레코드에는 `isTutorialSample:true`, 회사 ID, 소유 사용자 ID, `tutorial:` 접두사 ID가 있다.
- API `/api/tutorial/*`와 전용 저장소를 사용한다. 현장/견적/사진/자재/수금/정산 저장소를 주입하거나 변경하지 않는다.
- 생성은 중복 없이 실행된다. 삭제는 현재 회사·현재 사용자·현재 역할의 예시 묶음만 제거한다. 확인창 취소 시 유지한다. 조회만으로 삭제한 예시를 재생성하지 않는다.
- 예시 입력은 예시에만 저장된다. 작업 시작/완료 요청과 사진 선택을 체험할 수 있다. 사진 선택은 현재 화면에서 미리보며 실제 사진/NAS 저장소에는 업로드하지 않는다. 저장되는 것은 예시 설명/개수 등 예시 메타데이터이다. 기본 이미지 경로는 변경할 수 없다.
- 예시 견적 금액은 체험용 가상값이다. 자재단가 DB나 견적/정산 원장에 등록되지 않는다. 예시 보고서는 제출용 PDF가 아니다.
- 기존 프로젝트의 업무 저장소에 들어 있던 샘플(현장/PRICE 자재 등)은 새 튜토리얼 예시가 아니다. 기존 샘플이 실제 자료와 섞여 있을 수 있으므로 이름을 추정해 지우지 않는다. **예시 삭제 버튼은 새 튜토리얼 예시만 삭제한다.**

## 완료 상태 저장과 제한

진행상태는 회사+사용자+역할+튜토리얼 버전별로 서버 저장소와 브라우저 localStorage에 저장한다. 건너뛰기도 저장하여 재로그인 시 자동으로 다시 시작하지 않는다. 역할/회사/사용자가 달라지면 별도 상태이다. 요청은 순서대로 동기화하며 연결 실패 시 브라우저 진행상태를 보존한다.

현재 서버 `MemoryTutorialRepository`는 기존 앱과 같은 메모리 방식이다. 서버 재시작으로 서버 상태가 사라져도 같은 브라우저의 완료 상태로 복원할 수 있다. **서버 재시작 후 새로운 기기까지 영구적으로 완료 상태가 공유되는 저장은 아직 제공하지 않는다.** 브라우저 데이터를 삭제/차단하고 서버 상태도 초기화되면 가이드가 다시 나타날 수 있다. 다음 Supabase 작업 시 전용 저장소를 영구 DB로 교체한다. 예시 세션은 계속 업무 원장과 분리한다.

기본 예시 이미지 파일은 공통 정적 앱 자산이다. 사용자 예시 삭제 시 다른 사용자의 체험에 필요한 공통 파일까지 삭제하지 않는다.

## 입력 가이드

회사·거래처·현장·견적·작업진행자·사용자·자재·A/S·수금·완료보고서에 필드별 짧은 예시를 placeholder로 표시한다. 기존 검색 안내 등 명시적인 placeholder는 보존한다. 포커스 시 예시를 숨기고, 빈 값으로 빠져나오면 다시 표시한다. 실제 입력값과 색상을 구분한다.

`InputGuides`는 placeholder 속성만 설정하고 value/defaultValue/React 모델/저장 요청을 변경하지 않는다. 숫자는 공통 `QuoteNumberInput`/`GuidedInput`에서 입력 문자열을 별도로 관리하므로 0을 삭제한 상태를 유지한다. 계산·저장 시 기존 숫자 모델이 필요한 경우 빈 값은 기존 정책에 따라 0으로 해석한다. 기존의 유효한 기본 설정/자동 산출량/저장된 금액은 바꾸지 않는다. 자재단가의 미등록 여부 등 기존 검증 정책도 유지한다.

## 수정 위치

- `packages/shared/src/tutorial.ts`: 단계·문구·화면 도움말·예시 종류·ID와 버전. 구조 변경 시 `TUTORIAL_VERSION`을 올린다. 서버 단계 범위도 이 설정을 따른다.
- `apps/admin-web/app/onboarding.tsx`: 진행/강조/도움말/예시 체험, 화면 이동 매핑과 저장 동기화.
- `apps/admin-web/app/input-guides.tsx`: 공통 placeholder 규칙. 실제 값을 주입하는 코드를 추가하지 않는다.
- `apps/admin-web/app/quote-number-input.tsx`, `guided-input.tsx`: 빈 숫자 입력.
- `apps/api/src/tutorial.ts`: 회사/사용자 범위 전용 예시·진행상태 저장소 인터페이스와 API. 향후 `user_tutorial_progress`와 `tutorial_sample_sessions` 같은 분리 테이블로 교체할 수 있다.
- `page.tsx`, `mobile-workspace.tsx`, `operational-workspace.tsx`: 기존 화면 연결. 기존 권한 검사와 업무 컴포넌트를 재사용한다.

## 검증

프로젝트 빌드와 TypeScript 검사, 전체 API 테스트를 수행했다. 튜토리얼 API는 사용자·회사 격리, 중복 없는 생성, 편집·삭제·재생성, 진행 저장/초기화와 기존 현장·견적·거래처·사진·지출·수금·정산 보존을 검증한다. 필드 예시는 별도 단위 테스트와 실제 브라우저 저장 요청으로 확인한다.

브라우저 검증의 최종 결과와 화면은 아래에 기록한다. 화면 크기 검증은 Chromium을 사용하며 실제 iPhone Safari/Android 기기 설치 검증을 대신하지 않는다. 설치형 PWA는 서비스워커 및 설치 상태 플래그를 모사한 시나리오로 확인한다. 오프라인 업무 저장이나 실제 모바일 카메라/NAS 업로드 기능을 추가한 것은 아니다.

## 배포·보류 범위

Supabase 전환은 사용자 요청대로 보류 상태이다. OAuth 설정, 운영 인증 모드/환경변수, 운영 DB 마이그레이션은 실행하지 않는다. 기존 Render 서비스와 Docker 구성도 변경하지 않는다. 기존 미커밋 Supabase 준비 코드를 보존하며 이번 구현만으로 해당 준비 코드를 운영에 활성화하지 않는다.

### 확인 결과 (2026-10-14 UTC)

- 빌드와 TypeScript 검사 통과. 전체 API 테스트 91개 통과, 실패/건너뜀 0개. 튜토리얼 전용 4개 테스트에는 7종 실제 업무 조회의 200 응답과 삭제 전후 값 동일 비교가 포함된다.
- PC 1440×1000, iPhone 크기 390×844, Android 크기 412×915에서 관리자·직원·작업진행자 9개 조합의 강조·이전/다음·건너뛰기·다시보기·완료 저장·삭제 취소/확정·재생성을 확인했다. 튜토리얼 중 실제 업무 변경 API 호출은 없었다.
- 세 크기에서 회사·현장·거래처·견적·작업진행자·사용자·자재·수금·A/S·완료보고서의 입력 예시를 확인했다. 숫자 0을 지운 뒤 빈 값 유지, 최소 정보로 실제 현장 저장 시 placeholder 미포함 및 빈 주소/거래처/공사내용 유지, 예시 삭제 후 그 현장 보존을 확인했다.
- 실제 서비스워커가 활성화된 브라우저에서 iOS 설치 상태 플래그를 모사하여 도움말·예시 작업 시작/완료·사진 선택/저장·진행상태 초기화를 확인했다. 튜토리얼 API는 서비스워커 캐시에 저장되지 않았다. 실제 기기 설치/카메라 촬영은 미검증이다.
- 사진 체험 저장 시 읽기 전용 기본 이미지 경로가 전송되어 거절되던 문제를 수정했다. 클라이언트는 수정 가능한 예시 필드만 전송하며 서버는 기본 경로 변경을 계속 거부한다.
