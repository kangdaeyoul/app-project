# 견적 제출용 출력과 거래처·상세 UX

## 적용 기능

- 사용자 화면, 고객 PDF, 고객 Excel의 양식 명칭을 `견적 요약`, `기계 상세 내역서`, `전기 상세 내역서`로 통일한다. 원본 종로소방 XLSX와 내부 필드 `sections` 등은 유지한다. 실제 주소의 `을지로`처럼 고유명사는 치환하지 않는다.
- 회사 설정: 회사명/대표자/사업자번호/주소/전화/팩스/이메일/홈페이지/담당자/담당자 연락처/업태/종목/계좌/안내문구/로고/직인.
- 새 견적은 회사 기본정보를 복사한다. 저장된 `companySnapshot`과 `customerSnapshot`은 이후 기본정보 수정과 별개이다. 기존 스냅샷 없는 기록은 기본정보 변경 전에 당시 값을 보완한다.
- 견적 요약에서 수신처/거래처/현장/주소/견적일/유효기간/공사기간/회사정보/비고를 수정하며, 웹 미리보기에서 즉시 확인한다. 모바일 편집은 접기와 전체화면 미리보기를 사용한다.
- PNG/JPG 이미지 업로드, 삭제/재업로드, 10~60mm 크기와 직인 위치 조정. 파일 1MB/해상도 1천만 픽셀 제한. 원본 파일을 보존하고 처리 결과를 따로 보관한다.
- JPG 직인: Sharp로 sRGB RGBA 픽셀을 읽고 밝고 색 차이가 작은 배경의 알파를 낮춘다. 충분히 붉은 픽셀은 보존한다. 이미 투명한 PNG는 바이트 원본 그대로 사용한다. 복잡한 배경은 완벽히 처리한다고 보장하지 않으며 원본/결과를 확인하고 다시 업로드할 수 있다.
- 고객 PDF는 한글 폰트를 포함하고 견적 요약 → 기계 → 전기 순서로 출력한다. 로고/직인/회사정보/수신정보/금액/비고가 스냅샷 기준이다. 내부 원가·마진은 고객 DTO/출력에 포함하지 않는다.
- 종로소방 Excel은 원본 셀 스타일/병합/테두리/프린터 설정을 유지하면서 회사정보와 이미지, 명칭, VAT 포함 총액을 갱신한다. 입력 없는 비용/상세 행과 빈 그룹을 숨기고 상세는 페이지당 최대 22개 항목으로 나눈다. 시트 순서는 기계 전체 페이지 다음 전기 전체 페이지이다. 다른 회사는 원본 종로소방 로고·직인 없는 일반 Excel을 사용한다.
- 견적 복사에는 스냅샷/로고/직인/비고를 복사한다. 새 견적번호는 회사별로 자동 발급하며 기존 번호는 보존한다.
- 거래처: 기존 검색/새 등록/입력 안 함. 이름·사업자번호·담당자·전화번호의 즉시 검색. 거래처가 없어도 저장/출력 가능하고 빈 거래처 라벨과 `귀중` 문구를 출력하지 않는다.
- 거래처 관리: 기본정보, 사업자번호, 최근 견적일/건수, 과거 견적과 연결 현장. 관리자가 수정/삭제할 수 있다. 삭제는 비활성 보존 방식으로 과거 기록·연결·스냅샷을 유지한다.
- 견적 목록은 PC 표/모바일 카드. 행/카드에서 읽기 전용 상세를 먼저 연다. 수정 버튼으로만 편집한다. 검색/상태/공종/기간/정렬과 40건 단위 페이지를 제공한다.
- 목록 전용 `/quotes/index`는 품목 전체, 내부 원가, 회사 이미지 없이 요약만 반환한다. 상세 진입 때 전체 기록을 읽는다. 기존 `/quotes` API는 기존 기능 호환을 유지한다.
- 상세의 수정/복사/공유/PDF/Excel/미리보기 액션바는 고정된다. 공유는 실제 고객용 PDF 파일을 생성하며 Web Share 지원 시 파일을 공유하고, 미지원 시 다운로드한다. 외부 공개 링크는 생성하지 않는다.

## 권한과 캐시

- 회사/이미지/견적/거래처는 기존 회사 범위 및 API 권한을 검증한다. 다른 회사의 스냅샷/이미지 소유권 지정은 차단한다.
- 회사 기본정보와 이미지 교체는 관리자만 가능하다. 직원 견적 편집 시 법인명/대표자/사업자번호/계좌/로고/직인은 기존 값으로 유지하고 연락정보는 견적별 수정 가능하다.
- 인증 상태 조회에는 큰 이미지 원본과 직인을 포함하지 않는다. 앱 로고는 회사/내용 해시가 포함된 인증 경로로 제공하며 다른 회사의 로고 조회를 차단한다. 작업진행자에게 견적 회사 프로필/직인 원본을 전달하지 않는다.
- API 응답 기본은 `no-store`/`Vary: Cookie`; 버전 있는 로고만 개인 캐시 허용. 문서 다운로드도 오래된 캐시를 사용하지 않는다. 일시적 연결 오류 시 조회/문서 GET만 한 번 재시도하며 저장/변경 요청은 자동 재시도하지 않는다.

## 저장 범위와 운영 제한

기존 회사·견적·거래처 저장소는 **메모리 방식**이다. 이번 변경은 해당 인터페이스와 회사별 분리를 유지하며 스냅샷 구조를 추가한다. 같은 실행 중 기본정보를 수정/삭제해도 과거 견적은 보존되지만, 서버 재시작/재배포를 견디는 회사·견적 영구 저장까지 구현한 것은 아니다. 운영 입력이 있으면 재시작 전에 문서/자료를 별도 보관해야 한다. 자재의 기존 SQLite/PostgreSQL 저장은 변경하지 않는다. 이 작업으로 운영 DB 마이그레이션/초기화/삭제는 실행하지 않는다.

향후 PostgreSQL: `companies.quote_profile`, `company_assets(company_id, original_key, processed_key, version)`, `quotes(company_id, quote_number, company_snapshot, customer_snapshot)`로 이전할 수 있다. 영구 번호 카운터와 회사+번호 고유 제약이 필요하다. 기존 스냅샷의 이미지 버전은 기본 자산 삭제 후에도 보존한다.

## 검증

빌드/타입 검사/API 테스트 및 실제 브라우저 결과는 완료 보고와 함께 기록한다. 휴대폰 크기 검증은 Chromium 에뮬레이션이며 실제 iPhone Safari나 OS 공유 앱 전송을 대신하지 않는다. Web Share 지원 분기는 실제 파일을 생성한 후 공유 호출을 모사하여 확인한다. 외부 서비스 로그인정보와 운영 DB 접속값은 사용하지 않는다.

원본 XLSX의 스타일/프린터 설정, 비용 비노출, 100개 항목의 모든 출력, 한글 PDF, 스냅샷/이미지/회사 격리, 거래처 없는 저장과 수정·삭제 후 보존을 API에서 검증한다. 브라우저에서는 회사 설정과 PNG/JPG 업로드, 미리보기, 실제 PDF/Excel 다운로드, 검색 4종, 상세/수정/복사/공유, 모바일 카드를 검증한다.

### 최종 실행 결과 (2026-10-14)

- `npm run build`, `npm run typecheck`, `npm test` 성공. API 테스트 82개 통과, 실패/건너뜀 0개.
- Chromium 실제 브라우저 PC 1440×1000, iPhone 크기 390×844, Android 크기 412×915에서 회사 설정, PNG/JPG 직인, 로고, 크기/위치, 견적별 정보 변경, 미리보기, 저장/다시 열기, 기본정보 변경 후 보존, 거래처 입력 없음, 검색 4종, 신규 거래처, 목록/상세/수정/복사/공유와 PDF/XLSX 다운로드를 검증했다.
- 세 화면에서 거래처 관리 목록·사업자번호 검색·과거 견적, 기본정보 수정·삭제 후 과거 스냅샷 유지, 삭제된 거래처의 견적 다시 열기·편집을 검증했다. 가로 넘침과 브라우저 실행 오류 없음.
- 관리자/직원/작업진행자 1·2의 이메일 로그인과 데모 로그인 8개 흐름, 비활성 계정 차단을 실제 브라우저에서 확인했다. 회사 범위·권한 검증은 API 테스트에 포함된다.
- PDF는 실제 생성 파일을 텍스트 추출·페이지 렌더링하여 한글/이미지/금액/순서를 확인했다. XLSX는 ExcelJS로 시트명·순서·합계 셀·이미지 2개를 다시 읽었다. 원본 템플릿 스타일/인쇄 및 대량 항목은 API 테스트로 확인했다. Microsoft Excel/한컴 실제 앱에서 인쇄하는 검증은 실행하지 않았다.
- Web Share 분기는 실제 PDF 파일 생성 후 브라우저 공유 호출을 모사했다. 실제 iOS/Android 공유 앱 전송은 검증하지 않았다.
