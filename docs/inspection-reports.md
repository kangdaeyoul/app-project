# 점검지적사항 보수결과보고서

현장 상세 **보수결과보고서** 탭에서 지적사항 번호·내용·보수결과와 해당 현장의 전후 사진을 연결합니다. 보고서 초안을 저장하고 다시 불러올 수 있으며 항목 추가·수정·삭제·순서 변경을 지원합니다. 새 보고서를 작성하면 기존 보고서는 유지합니다.

## 출력 구성

- 전체 제출 모드의 첫 페이지: 선택한 표지 문서명, 현장명, 작업일자, 현재 회사 설정의 공사업체명, 이행조치 내용, 선택 입력한 원본 점검자료명, 작성일. 긴 표지 문구는 글자 크기를 조절하여 표지 한 장 안에 배치합니다.
- 보수결과 본문에는 점검번호 → 지적사항 → 보수내용 → 전 사진/후 사진 순서의 테두리 표를 배치합니다. 원본 번호를 유지하고 화면의 항목 순서대로 출력합니다. 표지 포함 여부와 사진 전용 출력은 아래 출력 모드를 참고하세요.
- 기본 6장형은 전후 3쌍, 8장형은 전후 4쌍을 A4 한 페이지에 배치합니다. 한 항목에 여러 사진을 선택하면 선택 순서대로 짝지으며 이어서 출력합니다. 대응 사진이 없는 경우 빈 칸에 안내 문구를 표시합니다. 번호·위치·짧은 설명을 사진 아래에 넣습니다.
- 100×150/150×100은 사진 방향과 비율의 기준으로 사용합니다. 실제 크기는 A4 여백·본문·6/8장 배치에 맞춰 자동 조절하고 사진 원본 비율을 유지하며 자르지 않습니다. 서로 다른 사진 비율과 지적내용 길이에 따라 한 페이지의 실제 사진 개수는 달라집니다.
- 긴 지적내용/보수결과는 별도의 본문 페이지로 이어서 전체를 출력한 뒤 해당 항목의 사진 표를 표시합니다. 짧은 사진 캡션은 말줄임할 수 있고 원본 설명은 기존 사진 기록에 유지됩니다.
- 고객 확인 서명란을 넣지 않습니다. 모든 항목을 하나의 PDF로 출력합니다.
- NanumGothic 한글 폰트를 내장합니다. 파일명은 `현장명_점검지적사항보수결과_작성일.pdf`입니다.

미리보기는 실제 PDF로 표시합니다. 내용을 수정하면 기존 미리보기를 폐기합니다. 새 보고서/다른 초안으로 이동할 때 저장하지 않은 내용은 확인 메시지를 표시합니다. 사진을 삭제하거나 전후 구분을 바꿨다면 보고서에서 유효하지 않은 연결을 해제하고 다시 선택해야 합니다.

## API / 권한 / 저장

- `GET /api/sites/:siteId/inspection-reports/source`: 현장·회사·사진·기본값·저장된 보고서 목록
- `POST /api/sites/:siteId/inspection-reports`: 초안 생성
- `PUT /api/sites/:siteId/inspection-reports/:id`: 초안 수정
- `POST /api/sites/:siteId/inspection-reports/preview`: 저장하지 않는 PDF 미리보기
- `POST /api/sites/:siteId/inspection-reports/generate`: 임시 파일 저장 후 PDF 다운로드

회사별 저장소 파티션과 서버 사용자 소속을 사용합니다. 관리자는 회사 내 현장, 일반 사용자는 `accessibleSiteIds`에 허용된 현장만 접근합니다. 읽기 전용 사용자는 초안/생성 파일을 저장하지 못합니다. 보고서 생성·수정 및 PDF 생성·응답은 회사/현장 감사로그에 기록됩니다. 사진 원본과 일일작업은 수정하지 않습니다.

현재 초안은 메모리 저장소이며 재시작 시 샘플을 제외한 기록이 없어집니다. PDF는 별도 `InspectionReportStorage` 포트를 사용하는 회사별 임시 저장소(30분, 최근 20개)에 보관합니다. NAS 키는 `companies/{companyId}/{siteId}/06 완료보고서/점검지적사항/{uuid}/{filename}`입니다. 실제 NAS/DB 연결은 없습니다.

## PostgreSQL 이전 구조

메모리 어댑터는 아래 관계를 정규화한 세 컬렉션으로 관리합니다.

- `inspection_reports`: id, company_id, site_id, work_date, created_date, original_document_name, layout, created_at, updated_at
- `inspection_report_items`: id, company_id, report_id, number, inspection, result, position
- `inspection_report_item_photos`: company_id, item_id, photo_id, stage, position

회사 범위를 포함하는 복합 외래키와 `(company_id, report_id, number, location)` 유일 제약, 항목·사진 위치별 인덱스를 적용합니다. 다른 현장의 사진과 반대 구분의 사진은 서버에서 거부합니다. 항목당 전/후 각 30장, 보고서 총 120장, 항목 100건까지 지원합니다. 사진 삭제 후에도 보고서 연결 ID와 과거 감사 스냅샷은 유지하며 재출력 시 누락을 확인합니다. 영구 저장 어댑터에서는 보고서/항목/사진 연결과 감사로그 갱신을 동일 트랜잭션으로 처리하세요.

종로소방 S001에 샘플 보고서 한 건이 있으며 기존 샘플 전후 사진 3장을 연결합니다.

## 제출문서 출력 모드

작성 화면에서 다음 모드를 선택합니다. 모든 모드는 PDF 하나로 미리보기·다운로드하며 파일 저장·회사/현장 권한·감사로그 방식은 동일합니다.

| 모드 | 구성 |
| --- | --- |
| 이행완료 보고서 + 보수결과 + 사진대지 | 1페이지 제출 표지, 2페이지부터 점검번호별 지적사항·보수내용과 전후 사진 표 |
| 보수결과 + 사진대지 | 표지 없이 점검번호별 지적사항·보수내용과 전후 사진 표 |
| 사진대지만 | 표지·지적사항·보수내용 없이 원본 점검번호·작업 위치·전후 사진과 캡션 |

표지 제목은 `소방시설등의 자체점검 결과 이행완료 보고서` 또는 `점검지적사항 보수결과보고서`를 선택합니다. 현장명·작업일자·공사업체·이행조치 내용이 포함됩니다. 이행조치 내용은 직접 작성하거나 보수내용으로 자동 요약할 수 있습니다(최대 1,000자). 요약은 보고서 항목의 원문을 변경하지 않습니다. 표지 한 페이지에 담기 어려운 문구는 생성 시 요약 안내를 표시합니다.

원본 점검번호를 문자열 그대로 유지합니다(예: `7-2`, `001`). 같은 점검번호의 여러 위치는 **같은 점검번호 세부항목 추가**로 분리하고 위치·보수내용·전후 사진을 각각 선택합니다. 같은 번호가 여러 항목에 사용되면 위치를 입력해야 하며 `(점검번호, 위치)`가 중복될 수 없습니다. 정렬해도 원본 번호를 자동으로 바꾸지 않습니다.

`사진내용` 공통 캡션 문구를 지정하면 `사진내용 | 옥내소화전 유량계 및 배관 작업 전/후` 형식으로 출력합니다. 미입력 시 기존 사진 설명을 사용합니다. 위치는 세부항목의 작업 위치를 우선 사용합니다. 사진대지만 모드에서는 지적사항·보수내용 입력 없이 사진과 번호·위치만으로 출력할 수 있습니다. 사진이 한 장도 없으면 해당 모드 생성을 거부합니다.

6/8장형 표 렌더링과 이미지 변환은 기존 `PhotoReportService`에 연결했습니다. 원본 사진 보존·한글 폰트·PDF 미리보기·사진대지 기존 출력 형식은 유지합니다.

저장 확장 필드: `inspection_reports.output_mode`, `cover_title`, `action_summary`; `inspection_report_items.location`, `photo_content`. 기존 초안에 필드가 없으면 기본값으로 읽습니다. 기존 `(company_id, report_id, number)` 유일 제약 대신 `(company_id, report_id, number, location)`을 사용하고, 번호별 그룹은 회사·보고서 범위 안에서 조회하세요. 다른 회사/현장의 사진 연결 제한은 유지합니다.
