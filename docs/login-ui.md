# 간소화한 로그인 화면

이번 변경은 UI와 기존 GET /api/auth/config 응답만 확장한다. 새로운 DB 마이그레이션은 없다.
이전 회사별 가입 작업의 007은 그대로이며 이번 UI 때문에 SQL을 추가 실행할 필요는 없다.
PostgreSQL/Session Pooler/SSL, 회사 멤버십·초대·승인·역할·회사 선택 로직은 변경하지 않는다.

## 표시할 로그인 방식

기존 /api/auth/config의 loginProviders 객체로 제공자를 표시한다.

- emailEnabled: AUTH_EMAIL_ENABLED가 미설정 또는 true이며 실제 인증 설정이 준비된 경우 true.
  기존 개발용 메모리 인증에서도 기본 true다. 명시적인 false 또는 잘못된 값은 표시하지 않는다.
- googleEnabled: AUTH_GOOGLE_ENABLED=true이고 Supabase 인증 설정이 준비된 경우에만 true.
  기본값은 false다. 운영에서 Google OAuth를 검증한 뒤 운영자가 명시적으로 활성화한다.
- kakaoEnabled, naverEnabled, phoneEnabled, appleEnabled: 구현되지 않아 항상 false.

환경변수는 로그인 UI 표시 설정이며 인증 엔드포인트나 실제 권한을 추가/삭제하는 설정이 아니다.
운영 환경변수는 자동 변경하지 않는다. 기존 설정 API를 재사용하며 별도 설정 API는 만들지 않는다.
미구현 제공자의 준비 중 안내/비활성 버튼, 테스트 계정 버튼, 긴 기능 소개, 빌드 버전 문구는
기본 로그인 화면에 렌더링하지 않는다. Google 계정 연결 UI도 같은 Google 표시 설정을 따른다.

## 화면과 가입 안내

공통 홈은 서비스명·짧은 안내·로그인·새 업체 등록 두 동작으로 줄였다. 로그인 후 역할은
기존 서버 멤버십이 결정하며 관리자/직원/작업진행자를 최초 화면에서 선택하지 않는다.

/c/[companySlug]는 회사 로고/회사명, 계정/비밀번호, 로그인 버튼과 보조 링크만 기본 표시한다.
비밀번호 찾기와 회원가입은 같은 줄의 낮은 우선순위 링크 스타일이다. 활성 Google만 선택적으로
하단에 표시한다. 로고/폼 크기와 페이지 높이는 작은 화면 및 키보드가 열린 높이에 대응한다.

회사 전용 화면의 회원가입은 회사 관리자에게 초대 링크를 요청하라는 안내만 제공한다.
가입할 회사를 임의로 입력/변경하는 폼으로 연결하지 않는다. 초대 가입 화면에서 기존 계정 로그인으로
들어왔다면 회원가입 링크는 검증받은 원래 /join/[inviteToken]으로 돌아간다.
최초 업체 관리자는 공통 홈의 새 업체 등록을 사용한다.

비밀번호 찾기는 기존 관리자 재설정 요청 안내를 유지한다. 이번 변경에서 자동 재설정 메일이나
새로운 비밀번호 변경 API를 구현한 것은 아니다. 기존 계정/비밀번호 인증 로직을 유지한다.

체험은 별도 /trial 화면으로 분리해 유지한다. 정상 로그인 화면에는 체험/테스트 버튼을 표시하지 않는다.
기존 trial API와 회사 격리, 데모 인증 엔드포인트도 유지한다.

- login-config.test.ts: 이메일 기본값, Google 명시적 활성화, 잘못된 값/미설정 인증/미구현 제공자 비표시.
- verify-tenant-ui.cjs: PC/태블릿/모바일의 두 동작 홈, 회사 브랜딩, 이메일 로그인,
  비밀번호 안내·초대 가입 링크, 기본 숨김/Google만 활성/이메일 비활성/모두 비활성,
  기본 화면 스크롤·가로 넘침 없음, 작은 높이에서 버튼 접근성, 기존 초대/회사 선택 회귀.

브라우저 테스트는 모의 API/인증을 사용하며 실제 Google OAuth의 운영 검증을 대신하지 않는다.

PC/태블릿/모바일 화면·제공자 표시·작은 높이에서 로그인 접근·초대 링크와 기존 인증 UI 브라우저 검증도 통과했다.
운영 환경변수/SQL/배포는 변경하거나 실행하지 않았다.
