# 변경이력 / 감사로그

현장 상세 **변경이력** 탭은 해당 현장의 기록을, 관리자 정산 메뉴 **감사로그** 탭은 현재 회사 전체 기록을 조회합니다. 최신 기록순으로 표시하고 변경일시는 서울 시간으로 표시합니다. 날짜 범위, 사용자, 현장, 작업종류, 대상종류로 필터링하고 페이지당 25건을 조회합니다. 상세를 펼치면 변경 전·후 값과 회사/대상/기록 ID를 확인할 수 있습니다. 삭제된 현장도 전체 로그의 현장 필터에 남습니다.

## 저장 모델과 기록 범위

`AuditLog`는 ID, 필수 companyId, 사용자 ID·당시 표시명, 대상 종류/ID, 작업 종류, 전후 스냅샷, UTC 변경일시, 정렬 순번, 사유, 관련 현장 ID·당시 이름을 저장합니다. `MemoryAuditRepository`에는 append/list만 있고 수정·삭제 API가 없습니다. 조회 결과와 저장 입력은 깊게 복사하여 반환 객체 변경이 원본 이력을 바꾸지 않습니다. 메모리 방식이므로 API 재시작 시 초기화됩니다.

기존 회사별 저장소 인터페이스를 `auditedRepository`로 감싸 실제 저장에 성공한 변경을 기록합니다. 샘플 초기화, 단순 목록 조회 및 거부된 입력은 변경 로그를 만들지 않습니다. 값이 동일한 저장소 쓰기는 생략하지만 수정일시가 바뀐 저장은 수정으로 기록될 수 있습니다. 원본 데이터 구조와 반환 DTO는 유지합니다.

- 현장 생성·수정·삭제. 삭제 API `DELETE /api/sites/:id`는 관리자 전용이며 deletedAt을 기록하는 보관 방식입니다. 일반 현장 목록·대시보드에서 제외하고 과거 일일작업/정산 참조는 유지합니다. 기존 화면에 삭제 버튼을 추가하지 않습니다.
- 견적 생성·수정·삭제·복사·계약전환. 복사 시 원본 견적 ID를 사유에 보관하고 계약전환 재요청은 새 변경이 없으면 중복 기록하지 않습니다.
- 작업진행자 생성·수정·비활성화 및 날짜별 가능 상태 변경. 연결된 현장/일일작업/지출에서 관련 현장을 찾습니다.
- 일일작업 생성·수정·상태변경 및 사용자재 개별 추가·수정·삭제. 작업 현장을 이동하면 전·후 현장을 모두 관련 이력으로 보존합니다.
- 사진 추가·설명 수정·삭제·순서변경. 삭제 후 자동 순번 재정렬도 실제 변경된 사진에 기록합니다.
- 자재구매/경비 생성·수정·삭제, 증빙유형/파일 참조 변경.
- 수금 등록·수정·삭제.
- 작업진행자 지급 등록·취소와 지급 결과에 따른 정산 요약의 상태/금액 변경. 일부지급·지급완료·미지급 변화가 전후 값에 남습니다.
- 매출/매입/작업진행자 세금계산서 상태와 승인번호 등 변경. 최초 상태 저장 시 이전 저장값은 null입니다.
- 원본 사진/사진대지 파일 저장 및 삭제. PDF/Excel 임시 출력 생성, 이미지·문서 다운로드/미리보기의 응답 전송 완료. 다운로드는 HTTP 응답 finish가 발생하고 정상 파일 응답일 때만 남기며 실패·중단된 응답은 다운로드 완료로 기록하지 않습니다. 원본 바이너리 대신 파일 키/형식/크기 등 메타데이터를 기록합니다. 내부 렌더러의 파일 읽기는 사용자 다운로드로 기록하지 않습니다.

임시 사진대지의 TTL/보관 수 제한에 의한 내부 메모리 정리는 사용자 파일 삭제와 별개이며 현재 사용자 삭제 이벤트로 기록하지 않습니다. 다운로드 완료는 서버 응답 전송 완료를 뜻하며 사용자의 로컬 저장 완료를 증명하지는 않습니다.

요청 body의 선택 항목 `auditReason`으로 500자 이내 사유를 전달할 수 있습니다. 미입력 시 시스템 작업 설명을 저장합니다. 행위자의 회사/사용자 ID·표시명은 서버의 CompanyIdentity에서 결정하며 본문 또는 사진 등록자 입력값으로 바뀌지 않습니다.

## 조회 권한

- `GET /api/audit-logs`: 현재 회사 관리자만 조회. 다른 회사의 관리자 권한으로 현재 회사 전체 로그를 열 수 없습니다.
- `GET /api/sites/:id/audit-logs`: 관리자 또는 서버가 부여한 현장 접근 권한 필요. 관리자는 삭제된 현장도 조회할 수 있습니다.
- `AuditAccess` 포트가 현장 접근 검증 및 공개 스냅샷 정책의 교체 지점입니다. 현재 일반 사용자는 신뢰된 CompanyIdentity.accessibleSiteIds에 있는 현장만 조회할 수 있습니다. 브라우저 입력에서 현장 권한을 받지 않습니다.
- 일반 사용자에게 견적 내부 원가·내부 관리비·마진을 제외하고, 변경 전후의 다른 현장이 접근 범위 밖이면 해당 현장 스냅샷을 가립니다. 현장 간 이동 로그의 현장 목록도 현재 조회 현장으로 제한합니다.

현재 로그인 없는 종로소방 샘플 관리자 실행은 유지됩니다. 실제 인증 시 CompanyIdentityProvider에 사용자 소속과 현장 접근 권한을 연결합니다. 감사로그를 조회하는 동작 자체를 다시 변경 로그로 기록하지 않아 조회에 따른 무한 기록을 방지합니다.

## PostgreSQL 이전

`audit_logs`의 권장 열: `id`, `company_id NOT NULL`, `user_id`, `user_display_name`, `target_type`, `target_id`, `action`, `before_values JSONB`, `after_values JSONB`, `changed_at TIMESTAMPTZ`, `sequence BIGINT`, `reason`. 현장 연결은 `audit_log_sites(company_id,audit_log_id,site_id,site_name)` 또는 JSONB 필드로 별도 보관합니다. 원본 현장/대상/사용자 삭제가 로그를 삭제하지 않도록 원본 테이블로 CASCADE FK를 걸지 않습니다. 이름/표시명은 변경 당시 값을 보관합니다.

인덱스: `(company_id,changed_at,sequence)`, `(company_id,user_id,changed_at)`, `(company_id,target_type,action,changed_at)`, 현장 연결 `(company_id,site_id,audit_log_id)`. 모든 조회는 서버 회사 조건을 적용하고 RLS로 보호합니다. 일반 사용자에게 감사로그 테이블 전체 SELECT를 직접 허용하지 않고 조회 정책을 적용하는 서비스로 공개합니다. 전후 값에 개인정보·재무정보가 있으므로 일반 사용자에게 관리자 원본 스냅샷을 보내지 않습니다.

향후 영속 어댑터는 도메인 변경과 감사 append를 같은 DB 트랜잭션으로 수행해야 합니다. 현재 메모리 어댑터는 동기 변경 직후 append합니다. 실제 DB 연결 시 메모리용 전체 컬렉션 비교 대신 변경 대상 행·자식의 전후 값만 같은 트랜잭션에서 읽습니다. 애플리케이션 DB 역할은 감사로그 UPDATE/DELETE 권한 없이 INSERT/허용된 조회만 부여하고 보관·파기 정책은 별도 관리 작업으로 구현합니다.
